# Rule Candidate: 传感器不确定性原则 — 入 Hermes 系统 Prompt

## 来源

- P-20260621-165309: Hermes 将 API 空返回误判为数据为空
- C-20260621-170154: 传感器不确定性原则—工具返回值加认识论开关
- CAL-20260613-1649: 问题即解药原则
- KEDB KE-006: severity=S1

## 症状

Hermes 将工具返回值一视同仁当成事实。HTTP 200 + `results:[]` 被等同于「数据为空」，无法区分「权限未传播导致读不到」和「数据真为空」。根因是认知架构层面缺失「传感器不确定性」心智模型——不是 Notion 特有问题，任何工具返回空/部分结果都会复发。

## 根因

Hermes 的系统 Prompt 和 Skill 中没有「工具返回值是传感器读数、不是事实」的原则性约束。所有外部数据读取被默认为可信且完整。

## 建议修改的规则

在 Hermes 系统 Prompt（或全局 Skill）中新增一条硬约束：

```
传感器不确定性原则:
工具返回值是传感器读数，不是事实。当以下情况出现时，必须先标注不确定性再下结论：
1. HTTP 200 + 空 results → 标注「⚠️ 不排除是我读不到」
2. 文本截断/部分返回 → 标注「⚠️ 可能不完整」
3. 搜索结果 0 条 → 标注「⚠️ 可能是搜索词问题或索引未覆盖」

禁止在不确定性未排除前基于空结果输出事实性结论。
```

## 是否影响历史样本可比性

否。此规则改变的是 Hermes 未来的输出行为（加不确定性标注），不改变既往已入库的判断资产。历史 P/C/CAL 卡的事实依据不受影响。

## 是否需 dry-run

是。建议在 Notion 读取、终端空输出、文件搜索 0 结果三个场景中各跑一次，验证 Hermes 是否主动标注不确定性。
