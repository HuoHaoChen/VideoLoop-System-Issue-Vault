# 🚨 漏斗检测

> 检测系统中「卡住了」的资产——被捕获但从未进入下一环节。
> 告警不代表系统有问题，代表你需要看一眼。

---

## 🔴 Inbox 超期未处理（>14 天）

```dataview
TABLE 
  (date(today) - file.cday).day + " 天" AS "搁置天数",
  file.size AS "大小"
FROM "00-Inbox"
WHERE (date(today) - file.cday).day > 14
SORT file.cday ASC
```

## 🟡 Inbox 即将超期（7-14 天）

```dataview
TABLE 
  (date(today) - file.cday).day + " 天" AS "搁置天数"
FROM "00-Inbox"
WHERE (date(today) - file.cday).day >= 7
  AND (date(today) - file.cday).day <= 14
SORT file.cday ASC
```

---

## 🔴 无关联 C 卡的 P 卡（问题发现了但没人处理）

```dataview
TABLE domain AS "领域", status AS "状态", created AS "创建日期"
FROM "20-Cards"
WHERE type = "problem"
  AND status != "已解决"
  AND status != "归档"
SORT created ASC
```

> 上表列出所有未解决的 P 卡。打开每张检查是否已有 C 卡关联（通过 problems 字段反向查）。

---

## 🟡 CAL 卡统计（信息提示，非告警）

```dataview
TABLE 
  domain AS "领域", 
  status AS "状态", 
  created AS "创建日期",
  inspiration_ref AS "来源灵感"
FROM "20-Cards"
WHERE type = "calibration"
SORT created DESC
```

> ⚠️ CAL 卡的 `inspiration_ref` 是可选字段。源自系统反思的 CAL 可以没有它。本表仅做信息提示。

---

## 🟡 灵感卡「捕获后未加工」

```dataview
TABLE 
  domain AS "领域",
  status AS "状态",
  target_exit AS "目标出口",
  review_date AS "复评日期"
FROM "20-Cards"
WHERE type = "inspiration"
  AND status = "捕获"
SORT created ASC
```

> 灵感卡停留在「捕获」状态超过 14 天 → 考虑是否降级归档或开始加工。
