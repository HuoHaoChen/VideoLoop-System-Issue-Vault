# 🔧 测试替身注入必须可机械证明

==已实施== · 测试隔离 · <kbd>S2</kbd>

---

> [!question]+ 修改内容
> 把「离线」从一个**形容词**改成一条**可失败的断言**。

---

> [!quote] 改了什么

```
(1) 注入点断言（治本）
    替换 transport 后，立刻断言模块级全局确实是替身：
        assert M.relay_transport is not orig_relay
    并在 finally 中无条件还原，避免污染后续用例。

(2) 绊线（治标，但独立有效）
    M.urllib.request.urlopen  -> 一旦被调用即 RAISE
    M.subprocess.run          -> 命令首词为 claude 即 RAISE
                                （非 claude 子进程如 keychain 读取放行）

(3) 通过判据（把绊线纳入结果）
    测试结束时必须满足 TRIPWIRE_HITS == NONE 才算通过；
    命中即视为测试自身违规，而不是被测系统失败。

(4) 超时收窄
    测试内把 RELAY_TIMEOUT / CLAUDE_TIMEOUT 压到 5s，
    使「意外真实调用」表现为快速失败而非 900s 挂起。
```

**效果**：同一测试 11/11 PASS 且 `TRIPWIRES_TRIPPED = NONE`，
「离线」由可机械核验的产物支撑。

---

| 判断 | 依据 |
|:-----|:-----|
| ==(1) 是根因修复，(2) 是兜底== | (1) 直接消除「注入点≠读取点」；(2) 在 (1) 未来再次失效时仍能拦住真实调用 |
| ==绊线必须计入通过判据== | 否则绊线只是日志，命中后测试仍会「通过」 |
| ==超时收窄改变了失败模式== | 从「挂起 900s 后被外部杀死」变为「5s 内明确报错」，可诊断性显著提升 |

---

> [!warning] 现行边界
> - 绊线拦的是**本进程**的网络与 CLI 调用；无法拦截被测系统以其他方式发起的调用。
> - 该改造只覆盖测试脚手架，不改变生产 runner 的任何行为。
> - `TRIPWIRE_HITS == NONE` 只证明「本次运行未触发绊线」，不等于「架构上不可能联网」。
