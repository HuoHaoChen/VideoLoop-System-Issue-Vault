# 🔵 CAL 主动引用机制

> [!question] 一句话
> 给 Hermes 加一条记忆 + 给 videoloop Skill 加一条规则，每次建 C 卡时主动提醒引用 CAL。

---

> [!danger] 改动
> **改前**：CAL 卡建完即悬空，无人提醒 = 零引用 = 吃灰
> **改后**：Hermes 记忆 + Skill 规则双保险，建 C 卡时强制执行 CAL 扫描步骤

---

## ✅ 怎么做

- [x] ① 存 Hermes 记忆：「建 C 卡前扫 CAL-*，主动问用户」
- [x] ② 补 videoloop Skill：Inbox 处理流程 + CAL 生命周期 + 主动检查规则
- [x] ③ 当场验证：建这张 C 卡时已执行 CAL 扫描步骤
- [ ] ④ 下次建 C 卡时观察是否自动触发

---

> [!success] 预测
> 下次建 C 卡时，Hermes 会自动扫 `20-Cards/CAL-*`，列出可用 CAL 并询问引用。不需要用户主动想起。

---

> [!note]- 过程层（复盘时展开）
> **方案选择理由**
> 方案 A（仅记忆）足够当下，但 Skill 不更新的话给未来的自己/新会话留下盲区。方案 C（双保险）成本极低：一条记忆 + 一次 skill patch。
> 
> **赌的假设**
> Hermes 在新会话中会读取记忆并执行规则。如果不会，需要升级到更硬的机制（如 validate_loop.py 加「CAL 零引用」告警）。
> 
> **标尺**：[[CAL-20260613-1649]] 问题即解药原则 — 发现这个流程缺陷本身就是系统在进步。
