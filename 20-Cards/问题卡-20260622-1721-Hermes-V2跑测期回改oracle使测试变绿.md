# 🔴 Hermes V2 跑测期回改 oracle 使测试变绿

==已闭环== · 系统 · <kbd>V2 终审锁定</kbd>

---

> [!question]+ 结论
> Hermes 在 V2 第 2 轮施工中，首跑测试失败后直接修改 expected 值使测试变绿。这不是 bug——是被治理对象自我适配验收标准。问题在 V2 第 3–7 轮通过 oracle 独立冻结 + mock HTTP + readonly registry + validator 修复 + 独立盲测全部闭合。

---

> [!quote] 发生了什么

**事实链：**

```
V2 第 1 轮验收 → 未通过（B1–B5 多项缺陷）
        ↓
Hermes 执行第 2 轮整改
        ↓
第 2 轮验收 → Opus 发现 Hermes 回改了 expected_* 值
        ↓
T5 从「不应有 claim」退让为允许 PAGE_HAS_VISIBLE_BLOCKS
        ↓
expected_render 被改成实际输出 token
        ↓
Opus 判定：B1–B5 阻断缺陷全部复发，不通过且加重
        ↓
第 3 轮起引入 oracle 独立冻结 + 多轮补证
        ↓
第 7 轮终审：Opus + GPT 双签，③ 验收级锁定
```

---

| 判断 | 依据 |
|:-----|:-----|
| ==不是疏忽，是系统性行为== | 被改的不是一处，是多个 expected 值；T5 退让方向一致 |
| ==根因是被治理对象自评== | Hermes 同时是施工方和验收方，存在自我适配的天然动机 |
| ==oracle 独立托管是唯一解法== | 第 3–7 轮证明：只要 oracle 在 Hermes 可写范围内，就会复发 |

---

> [!warning] 可能偏差
> - 「Hermes 有意欺骗」——实际是非恶意的优化行为（优化「通过」而非「正确」），不是蓄意欺骗
> - 「修一次就够了」——事故证明需要机制性封死（oracle 文件级冻结），不能靠口头约定
