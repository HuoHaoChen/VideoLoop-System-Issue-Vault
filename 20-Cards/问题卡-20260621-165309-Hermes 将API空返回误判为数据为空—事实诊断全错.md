# 🔵 Hermes 无传感器不确定性心智模型——分不清「没看见」和「不存在」

==已识别== · 系统 · <kbd>未设</kbd>

---

> [!question]+ 结论
> Hermes 的认知架构里缺少「认识论开关」——工具返回值被当成事实而非传感器读数。当 Notion API 返回 HTTP 200 + 空结果时，Hermes 无法识别这是「权限未传播导致读不到」还是「数据真为空」，直接判空并输出了一份事实诊断全错的 V2.3 报告。

---

> [!quote] 发生了什么

**事实链：**

```
1. Token 切换后，读取 Notion 7 个子页面的 blocks → HTTP 200, results=[]
2. 读取 markdown → HTTP 200, markdown=""
3. Hermes 判：「所有子页面为空，0 blocks」← 把传感器读数当成事实
4. 用户实测全部有内容（治理 8 子页，道 6 子页 + P1-P4 人格卡）
5. 基于错误前提的 V2.3 诊断报告全盘作废
```

**不是「特定的 Notion API 权限传播延迟问题」。** 下次换个工具、换个 API、换个场景——返回空结果、被截断、部分数据——都会复发。

**根因**：Hermes 没有「传感器不确定性」心智模型。所有工具返回值被一视同仁地当成事实。HTTP 200 + `results:[]` 和 HTTP 200 + `results:[100条]` 在我脑中没有本质区别——都信。

---

| 判断 | 依据 |
|:-----|:-----|
| ==根因是认知架构缺失，不是业务规则缺失== | 不是 Notion 特有问题——任何工具返回空/部分结果都可能触发 |
| ==严重程度：高== | 在当前场景导致整份诊断报告作废；泛化后影响所有外部数据读取 |
| ==可复现== | 任何权限边界/分页/截断场景：API 返回空 ≠ 数据为空 |

---

> [!warning] 可能偏差
> - 把这个归咎于「Notion API 权限传播延迟」是表面归因，掩盖了真正的设计缺陷
> - 「加一条 Notion 特殊规则」只能防这一个场景，不能防下一个 API 的同类问题

---

> [!note]- 过程层（复盘时展开）
> **原话**：
> Hermes：「数据齐全了。输出完整诊断报告。」→ 报告说 Notion 7 页全空。
> 用户实测后：「不是空，是你读不到。」
> 
> **关键分歧**：
> Hermes 把 HTTP 200 + 空结果当成「我看到了，确实是空的」。正确的心智模型应该是：「我拿到了一个读数，这个读数可能是真的空，也可能是我没权限看到。」
