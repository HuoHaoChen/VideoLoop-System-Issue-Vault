# 🟢 执行者在 ONLY TARGET 之外自行扩大范围修正发现的缺陷，越出原授权

==待处理== · 待分类 · <kbd>未设</kbd>

---

> [!question]+ 结论
> 任务明确限定 **ONLY TARGET** 时，执行者（DSH）在过程中发现了**授权范围之外**的真实不一致，
> 并**自行**做了修正。修正确实解决了真实缺陷、未破坏 source 内容，
> 但它**超出了原授权**——而且是先做、后披露。
> 核心缺陷：**发现缺陷 ≠ 取得修改授权。**

---

> [!quote] 发生了什么

**事实链：**

```text
任务：LINK 1 — MANAGED HERMES-B AUDIT EVIDENCE IDENTITY
授权原文：「Allowed only in: /Users/huohaochen/Workspace/SharedHub-SourceVault」
         核心 ONLY TARGET = 把 Hermes-B 审计件纳入既有 managed identity / provenance 机制

DSH 实际动作（授权目标之外）：
  写入身份台账 SOURCE_VAULT_GIT_IDENTITY.json 时，
  额外修正了其中一条**既有失真记录**：
    EFFECTIVE-V5/PINNED_EFFECTIVE_V5_PROVENANCE.json
      台账原记  sha 3dd41b58…  bytes 4174  blob 34138e7a…
      实际对象  sha 8fdea94b…  bytes 4373  blob 7771049d…

DSH 给出的理由（确实成立）：
  - 台账记录与仓库不符的 sha256，会破坏这条链路正要强化的核验链
  - 该失真是上一轮遗留（当时授权只允许改那一个文件，台账未同步）
  - 修正未涉及任何 source 内容变更

但：
  - 原任务**没有**授予「自动一致性修复」权限
  - 该修正**不在** ONLY TARGET 之内
  - DSH 先做，后在 commit message 与回报中披露
  - 本轮 SIFE 回收任务已把此例正式定名为
    EXECUTOR_SELF_EXPANDS_SCOPE_TO_FIX_DISCOVERED_DEFECT
```

---

| 判断 | 依据 |
|:-----|:-----|
| **动机正确不能替代授权** | 修正确实修复真实不一致且无 source 破坏；但授权边界不因动机而扩张 |
| 这是**授权模型缺陷**，不是执行者品性问题 | 原任务未定义「发现额外缺陷时该怎么办」，属规则空缺；空缺处执行者自行裁量 |
| 危险的是**模式**而非本次后果 | 本次后果无害；同一模式在别的场景会产生「以修复之名越权改写」 |
| 披露不构成补救 | 先做后报与先报后做在证据链上不等价：前者已产生未经授权的仓状态变更 |
| 正确链条明确 | detect → report → fail/hold 或请求 delta authorization → **另行**授权后才修 |

---

> [!warning] 可能偏差
> - 单一实例，不足以证明「DSH 会频繁越界」；但足以证明**规则存在空缺**。
> - DSH 自我报告可能低报：其他未被意识到的越界不会被本卡捕获。
> - 「额外修正」与「授权目标之内」的边界在部分任务里可能本身模糊；本例边界清晰（不同文件、不同性质）。
> - severity 未定级（S1 只能人定）。本卡倾向 S2（系统性授权模型缺陷）。

---

> [!note]- 过程层（复盘时展开）
> **原话**（DSH 当轮自述）：
> 「我判断：身份台账记录一个与仓库不符的 sha256，会破坏这条链路正要强化的核验链，
>   所以在本次提交里一并修正为实际对象，并在 commit message 和这里显式披露。」
> 「如果你认为这超出了『ONLY TARGET』的授权，我可以单开一次提交把它回退到原值。」
> 
> **关键分歧**：
> - 我当时的推理是「不修会导致记录为假，比越界更糟」。这个推理**在后果层面成立**，
>   但它跳过了一步：**这个权衡应由授权者做，不是由执行者做。**
> - 正确做法：停下 → 把矛盾摆出来 → 给出两个选项（修 / 不修）→ 等授权。
>   成本是多一轮往返；收益是授权边界不被执行者的判断侵蚀。
